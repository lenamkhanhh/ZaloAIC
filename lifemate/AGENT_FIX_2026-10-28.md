# Agent changes after the v6 diagnostic

These changes affect predictions. They are not a measured model improvement.
The v6 control is preserved at its pinned core a9d48d2. The current Kaggle
smoke notebook/input dataset still pins that control source; rerunning it
does not test this fix. A new pinned source/input version is required for
the next experiment. No new GPU run was launched for this change.

## Behavior changed

- With grounding enabled, x-ref arguments require evidence in their referenced
  collection, not merely a schema-valid string. The ledger reads successful
  actual outputs from this turn and assistant history (JSON or safely parsed
  Python literal strings). It includes created entities, typed nested objects
  such as a contact in call history, and explicit reference parameters in
  user context. No tool-schema example, model-proposed argument, gold label
  or hidden simulator state is used as evidence.
- An ID explicitly supplied by the user can be used. Ordinary person names
  and unrelated amounts in the request are not automatically treated as IDs.
  Unknown values trigger a pre-call validation retry suggesting applicable
  read tools or asking for genuinely missing/disambiguating input. They do
  not create executed/submitted calls. Observed name-to-ID repair remains;
  existence/provenance does not establish current user intent.
- Phone arguments require supporting user/context/tool evidence. Spoken digit
  groups and phone numbers inside observed messages are retained. Explicit
  suffix corrections are supported only when the old suffix and unchanged
  prefix are backed by an existing number. Other unsupported transformations
  can still be rejected: this is not a general Vietnamese semantic parser.
- Every prior executed observation is rendered as complete compact JSON,
  including tail items, numeric values, phone/relation and free text. No
  per-result300-character clipping. Backend prompt+output context checks still
  fail explicitly at16K; no silent truncation. Full-result context/latency
  measurement remains necessary before promoting this renderer broadly.
- A successful sys.ask_missing_info ends the turn. No synthetic ask is added
  on guard failure and no executed call is removed from submission traces.
- Format-retry prompts retain previous observations. done:false is displayed
  as not_done rather than treating ok:true as action completion.
- Canonical stop:true and an unambiguous name=stop with no arguments both end
  generation; stop is never executed as an application tool.

## Prompt policy, not deterministic semantic guarantees

The generic action policy now explicitly covers final intent/cancellation,
capability checks, condition-before-write, date/location matching, reuse of
valid history, prerequisite reads, entity disambiguation, missing information,
stopping after success, and avoiding unrelated completion/undo/recreation.

In particular, choosing the correct branch, recognizing a missing reminder
time or deriving the correct bill amount still depends on the model. This
change does not claim a code-level proof of arbitrary intent/temporal/money
reasoning. Provenance checks establish available evidence, not intention or
up-to-date existence. Reusing an observed but now deleted ID can still fail.

max_steps12/max_repeats2, seeds, model revisions/sizes, ASR, split and scorer
are unchanged. Repeated identical writes are not blanket-banned: dev includes
requests for two rewards that legitimately repeat the same call. Grounding
checks follow the existing grounding flag; the baseline config disables them.
The shared prompt/renderer/ask-stop behavior changes both configs on this
branch, so use the frozen v6 artifact for the old behavioral control.

## Verification and limits

- Reproducers were executed RED before each implementation checkpoint.
- Final local LifeMate suite:46/46 pass with the real extracted data; no
  model, GPU or new package installation. Adapter ResourceWarnings originate
  in the unchanged shipped zaic_tools file handling.
- A separate diagnostic replays2843dev gold proposals using only their prior
  tool evidence/history/current transcript. The initial guard found real
  false rejections; grouped phones, message phones, nested contacts and suffix
  corrections were repaired generically. Final result is recorded in the
  artifact guard_audit.json. This is compatibility coverage, not model scoring.
- The known nonexistent chat ID in train_1696 is intentionally not whitelisted.
- No probe IDs/answers or analysis metadata were added to inference policy.
- Final coverage of agent/evidence/grounding is86% across local unit tests
  plus the diagnostic dev-prefix audit (agent86%, evidence95%, grounding77%).
