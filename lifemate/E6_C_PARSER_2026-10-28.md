# E6-C opt-in pseudo-call boundary

Only `NativeGenerator(..., reject_pseudo_calls=True)` enables the E6-C parser boundary. Default native and legacy behavior remain unchanged. Pattern is the preregistered narrow anchored `app.tool(` prefix after whitespace stripping. No eval, conversion or execution of pseudo-code occurs; it becomes NativeFormatError, an invalid proposal, and follows existing validation retry (three attempts per step). The generator retains pseudo_call_caught/format_valid:false diagnostics. Normal prose, explicit stop, existing tagged calls and bare-JSON rejection retain V10 semantics.

Scope: parser-only E6-C versus native V10 control, eight cached dev ASR inputs from V7. Evidence-first E6-B and reminder E5 rules are not included. A parser-confirmed channel result is not an intent improvement or default adoption.

Verification: six new synthetic tests RED before implementation (missing opt-in interface), then 13/13 native+boundary tests GREEN; full LifeMate 59/59; native_contract coverage 92%. Tests cover prefix boundaries, opt-in compatibility, tagged/prose/stop preservation, fake loop pseudo->retry->tagged ask, and three-attempt exhaustion without execution. Existing simulator ResourceWarnings are unchanged. No seed, model, scorer, split, guard or simulator changes.

Commands: python -m unittest lifemate.tests.test_pseudo_call_boundary -q (RED); python -m unittest lifemate.tests.test_native_contract lifemate.tests.test_pseudo_call_boundary -q (GREEN); coverage run/report on both modules; LIFEMATE_DATA set explicitly for python -m unittest discover -s lifemate/tests -q.
