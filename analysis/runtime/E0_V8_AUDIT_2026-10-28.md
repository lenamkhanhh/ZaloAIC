-0003first invents phone; provenance blocks it before execution. Model then
 searches and uses the observed actual phone for50000topup. It next invents
 a contact ID, which is also blocked. Searching 'co Mai' returns empty;
 model fails to broaden/resolve query, repeats it, and emits top-level ask
 tool_name/params without arguments. These are observable downstream failures,
 not a missing-current-transcript problem. The original transcript contains
 an amount referring to a bill, yet list_bills is never called.
-0116understands the reminder target with gold current input but uses
 2026-11-19T10:30:00+07:00 rather than asking missing time. ID provenance is
 not a semantic time-derivation validator; the prompt-only rule did not work.
-0025reads two Minh candidates and chooses one, with both contact_id and
 phone_number. Provenance proves the selected values were observed, not that
 the user intended that candidate. Gold asks for disambiguation. It also
 writes a conditional phrase into event.title before checking rain.
-0016conflates 'reschedule calendar' with 'create reminder', then completes
 the reminder and sends a claim that the match was rescheduled. Correct
 current transcript improved task recognition but did not make the action
 sequence faithful to the request.
-0049uses a real savings account by the end, but wrong amount and extra
 operations produce wrong state. Native validator tolerates extra account_id
 on get_balance; no declared x-ref exists on that undeclared argument.
