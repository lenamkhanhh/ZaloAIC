# E7 Phase 0 v1: partial, shadow-only provenance contract

No inference integration and no GPU. Pure assess(call,tools,current_request,context,observations,history) accepts no label/sample ID/future state. Inputs are current text, visible context, previous successful observations and history only. The runner may use labels solely to construct a causal gold-prefix diagnostic and to measure decision outcomes. No proposed call is executed by the guard.

Scope: catalog kind=write, present catalog-declared temporal names time/start/end/date/schedule_time/due_date/times or *_time/*_date or schema format date/date-time; numeric amount/quantity/threshold and threshold_*. Unknown tools, reads/meta, absent required fields, unmonitored properties stay outside this guard. Existing validator owns schema/required errors. Three decisions per scoped argument: ALLOW positive implemented evidence; BLOCK conflict or missing hour within an implemented unambiguous rule; UNKNOWN unsupported parsing/entity/reference. Call status BLOCK if any blocked argument, otherwise UNKNOWN if any unknown, else ALLOW. UNKNOWN is never silently treated as allowed or as false-block. Shadow always records it without taking action.

Implemented positive rules: numeric/limited Vietnamese word clocks with AM/PM, explicit date/relative day/weekday, request explicit now and one future minute/hour offset, one uniquely selected observed event shifted by one relative delta, simple units and word numbers, uniquely pointed bill amount, half of a uniquely pointed observed base. Date arithmetic cannot invent an hour. Context clock may anchor explicit now/relative arithmetic/calendar date, but cannot itself supply an unspecified reminder hour. A supplied literal cannot be shared between compound tasks without binding; those cases are UNKNOWN.

Observed IDs must also have a matched request entity. Equality or ID existence alone does not establish intent. Pointing uses a deliberately limited lexical entity matcher (multiword name/title/label/provider, explicit ID, basic bill-type language aliases). This is a heuristic, not general coreference or intent proof. Failed observations are excluded. History is considered only for a request reference, never just because a value exists there. Unique past matching entity/slot may support explicit refer-back. Supersession markers are UNKNOWN, not blanket invalidation. Unsupported multiple operations, corrections, ranges, inherited update dates and multivalue time lists are UNKNOWN. No assumption that a half equals50.

Important limitations registered BEFORE dev audit: implicit/complex reference resolution, field-level supersession, ambiguous date/name language, clause-specific numeric source, complicated Vietnamese numbers/time syntax and expression binding are not fully supported. A synthetic pass is not a claim of zero false-block. Full-gold scan is a screening oracle-input diagnostic; no unseen-ASR claim when only20 ASR caches exist. For missing ASR mark UNAVAILABLE, do not substitute gold and call it ASR.

Protocol corrections: (1) G4 hash equality applies to initial/pre-interception prompts; guard feedback necessarily changes later prompts. (2) Reporting tests have17 ordinary V13 plain stops as negatives and2 key=value positives, not19 negatives. (3) Known fills are identified by sample/arm/generation/argument in a diagnostic manifest only. (4) Resolve verdict partition before any future GPU: CPU_NOT_READY if any gold BLOCK or required fill not BLOCK (UNKNOWN does not pass); otherwise shadow-ready is only an engineering gate, never evidence of block->ask recovery. Any live legitimate-call BLOCK invalidates future interpretation. GPU is outside current authorization/phase.

Outputs: all40 V13 traces, every generation proposal with present scoped arguments including validator rejections, with both actual ASR and gold-text diagnostic decisions using the same observation prefix; all dev gold writes outside the20, with prior gold tool results only. Labels are not fed to assess. Record gold BLOCK as candidate false-block, independently review label semantics; record UNKNOWN separately. Never retune silently against gold failures to force readiness.

## Version history and v3 limitations

V1 is preserved as an initial screen, not hidden:23 synthetic tests,40 candidate gold false-blocks,5/6 known fills blocked. An independent read-only reviewer derived expectations before reading code and reproduced four general failures: event-relative 'nữa' anchored to now, number borrowing across slots/tasks, ignored weekday modifier, and substring ID matching. V2 addresses those with synthetic regressions; it also abstains on partial numeric expressions, unbound end durations, implicit event-completion/pending intent, mixed operations and date refer-back. V2 had1 remaining candidate false-block. V3 fixes the separate lexical bug interpreting the ordinary word 'chính' as 'chín'+h. All33 tests pass;32/33 are not a static development-set label list, and none contains a contest sample ID.

Scope is intentionally partial. Compound clauses including 'và', unsupported arithmetic/modifiers, uncertain date/field binding and supersession yield UNKNOWN. This increases abstention; reduced BLOCK counts are not improved true-allow coverage and never justify 'zero over-rejection'. A later learned or comprehensive semantic resolver would be a separate design, not an implicit promise of this regex prototype. Four independent review findings are closed by a bounded recheck, not a proof of all allow/block rules.

G2 requires positive gold coverage as well as no blocked gold and all known fills blocked. Any UNKNOWN among monitored gold writes leaves CPU_NOT_READY. No GPU phase is authorized by a passing unit test or by a hypothetical shadow-ready outcome. Existing runtime agent, parser, seeds, configs, simulator, scorer and model weights remain unchanged.
